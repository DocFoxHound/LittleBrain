# Data-only brain checkpoints

The game bridge and research tools now save a versioned JSON manifest and compressed numeric buffers. The reader accepts a fixed set of brain records and fields, preserves shared arrays and random generators, and checks buffer types, dimensions, size limits and population indices. Brain.save still replaces the destination atomically. Legacy object-format saves are rejected. The source viewer uses a new cache name so that it develops a fresh brain while leaving earlier caches on disk. Fading-precision snapshots use the same data format and can be regenerated by running the experiment.

On CPU seed 0, a developed 18,944-neuron reference brain occupied 18,726,269 bytes on disk. Its reloaded copy matched its learned weights, rate vector, shared random generator and three subsequent wake steps. The two generators also agreed after sleep. The integrated runtime checks passed, including all 187 mapped populations, scheduled overnight rewiring and learned checkpoint exchange through the external game bridge. The standalone archive tests cover malformed files, unsupported records, forbidden array types, truncated buffers and preservation of an existing save after a failed write.
